# Native Mouse-on-UI (world creation → main menu → character editor)

**Goal:** Make the mouse meaningful on CSE's text/UI menus, in priority order:
world creation, main menu, custom character editor — then inventory, crafting,
vehicle menu. Native input (SDL), **not** ImGui.

**Status:** implemented on branch `feat/native-mouse-ui` (2026-09-04).

**Reference:** CDDA pinned @ `5b915aea09` — its mouse-UI is ImGui-bound and
offers nothing to cherry-pick. CSE's own machinery is the reference: the
construction-mouse-preview commit `01ee91ff41` (review separately; not merged
here), and `sdltiles.cpp` / `input.cpp` for the mouse pipeline.

## Why this is not a CDDA port

Verified, do not re-derive:

- CSE/BN's `uilist` (in `src/ui.cpp`/`ui.h`) is pure SDL/ncurses — **zero ImGui**
  references.
- CDDA's `uilist` mouse support is **100% ImGui**.
- CDDA has **no pre-ImGui SDL `uilist` mouse hover/click implementation**.
- Therefore "mouse on the UI" was **written for CSE natively**, reusing the
  existing `input_context` / `MOUSE_MOVE` / `SELECT` plumbing from
  `01ee91ff41`.

## WIP branch defects (do not merge wholesale)

Branch `feat/construction-mouse-preview` / commit `8bd7bc75ff` had useful
hit-testing ideas but **`get_mouse_cell()` treated SDL pixels as terminal cells**
in the tiles build. CSE reimplemented conversion using `get_window_dimensions()`
and scaled font size in `sdltiles.cpp`.

## What shipped

### Foundation

- [x] `input_context::get_mouse_cell( catacurses::window )` in `input.h`,
      `input.cpp` (curses), `sdltiles.cpp` (tiles pixel→cell).
- [x] Shared helpers in `ui_mouse.h` / `ui_mouse.cpp`: list, rectangle, tab,
      bracket-tab, and crafting-subtab hit testing.
- [x] Unit tests in `tests/ui_mouse_test.cpp` (`[ui_mouse]` tag).
- [x] Cached cursor options: `mouse_cursor_show`, `mouse_hide_kb` wired in
      `options.cpp` and used from `sdltiles.cpp` (replaces repeated
      `get_option( "HIDE_CURSOR" )` lookups).

### Generic uilist

- [x] Hover highlight and left-click activation in `ui.cpp` using
      `uilist_entry::drawn_rect`.

### Priority screens

- [x] Main menu (`main_menu.cpp`) — existing screen-space button maps.
- [x] World creation (`worldfactory.cpp`) — world list, mod lists, worldgen tabs.
- [x] Character editor (`newcharacter.cpp`) — all editor tabs via shared helpers.

### Complex selectors

- [x] Inventory (`inventory_ui.cpp`) — column/entry hit testing with page offsets.
- [x] Crafting (`crafting_gui.cpp`) — category tabs, subtabs, recipe list.
- [x] Vehicle install (`veh_interact.cpp`) — install tabs + filtered part list.
      Repair/remove/overview loops still keyboard-only (overview rows are
      variable-height; deferred).

### Layer 1 (pre-existing)

Verified present from `e1b3ada5b0`: `ENABLE_MOUSE` option, event suppression
when disabled, X1/X2 side-button capture, cursor hide/show modes.

## Out of scope (deliberately)

- ImGui/IMTUI adoption.
- Drag, double-click, hover tooltips.
- Vehicle overview variable-height row mouse (harder; keyboard path unchanged).
- Construction mouse preview merge (`01ee91ff41`) — review when rebasing that work.

## Constraints & verification

- Additive only; keyboard navigation unchanged when the mouse is idle.
- Build: `cmake --preset cse-ninja` (or `cse-msvc`) → `cataclysm-bn-tiles`.
- Tests: `CATA_TEST_COMPUTE_ACCELERATION=cpu cata_test-tiles "[ui_mouse]"`.
- Rotate repo-root exe after each build (content-based compare).
- Playtest each screen with mouse **and** keyboard.
